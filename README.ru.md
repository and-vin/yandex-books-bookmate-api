Неофициальная, восстановленная из трафика карта REST- и GraphQL-API сервиса Яндекс Книги / Bookmate. У сервиса нет публичного API и официальной документации — этот репозиторий описывает факты, наблюдаемые в реальном трафике мобильного приложения и веб-ридера.

**[Открыть интерактивный справочник по API →](https://and-vin.github.io/yandex-books-bookmate-api/)** (рендер `openapi.yaml` через [Redoc](https://redocly.com/redoc))

## Что внутри

- **[`openapi.yaml`](./openapi.yaml)** — спецификация [OpenAPI 3.0](https://spec.openapis.org/oas/v3.0.3): REST-пути, форма запросов/ответов, схемы моделей. При каждом пуше проверяется валидатором [`openapi-spec-validator`](https://github.com/python-openapi/openapi-spec-validator). У каждого пути есть поля `x-verified`/`x-verified-date` — видно, подтверждён ли факт живым запросом или это допущение из стороннего проекта.
- **[`API.md`](./API.md)** — всё, что не выражается в OpenAPI: хосты, авторизация (OAuth-токен и cookie-сессия), два разных GraphQL-шлюза, особенности формы ответов, рейт-лимиты, форма ошибок, а также список эндпоинтов, которые были проверены и подтверждённо **не существуют**.

## Зачем это нужно

У Яндекс Книг (российская сторона Bookmate, отдельный бэкенд с 24.02.2022) нет опубликованного API. Существующие сторонние клиенты расходятся друг с другом в именах полей, форме ответов и даже в том, работают ли некоторые эндпоинты вообще. Этот репозиторий там, где возможно, сверяет такие утверждения с живыми ответами сервера и фиксирует актуальное поведение — включая задокументированный список расхождений с другими open-source клиентами (см. `API.md`, §5).

## Для кого это

Для разработчиков, которые пишут инструменты вокруг своего аккаунта Яндекс Книг / Bookmate: экспорт и синхронизацию библиотеки, статистику чтения, резервное копирование, ботов или клиенты на любом языке — репозиторий не привязан к языку программирования (чистый OpenAPI + Markdown, без кода).

## Границы и ограничения

- **Неофициальный и нестабильный API.** Это закрытый API без гарантий стабильности — пути, поля и вайтлист GraphQL-операций могут поменяться без предупреждения.
- **Эндпоинты расшифровки контента намеренно не документированы** (`content/v4`, `metadata/v4`, `playlists.json`, `metadata.json` для комиксов, пути файлов содержимого EPUB). Формальная схема с телом на расшифровку платного контента была бы готовым рецептом обхода защиты и нарушала бы пользовательское соглашение сервиса — см. `x-content-extraction-excluded` в `openapi.yaml`.
- Не каждый путь проверен вживую; непроверенные записи явно помечены (`x-verified: false`) и обычно указывают, из какого стороннего клиента взяты.
- Использование этого API, особенно операций записи и пакетных запросов, — исключительно на свой риск и с учётом пользовательского соглашения сервиса.
